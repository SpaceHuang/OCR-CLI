# OCRX PDF 内容感知处理需求 v0.2

状态：Draft  
日期：2026-08-24  
工作名称：PDF 智能分流（PDF Content-aware Routing）  
适用产品：`ocrx scan`

## 1. 背景与问题

当前 `ocrx` 将 PDF 页面统一渲染为图片并交给 OvisOCR2。该路径适合扫描件和以图片承载信息的 PDF，但对原生电子 PDF 存在明显浪费：许多论文、合同、报告和电子书已经包含可复制的文字、字符位置、字体和页面对象信息。继续对这些页面执行视觉 OCR，会增加模型下载与初始化等待、推理耗时、内存和能耗，同时可能引入错字、漏字和格式损失。

本需求为 PDF 增加内容感知处理分支。产品应判断 PDF 及其页面是以可靠的原生文字为主、以图片为主，还是两者混合，并选择直接提取或 OCR。两条路径最终必须进入同一份结构化页面文档和输出流程，对用户与 Agent 保持稳定契约。

## 2. 目标

### 2.1 产品目标

1. 对可靠文字层为主体的页面，不加载 OCR 模型，直接提取文字及可恢复的格式、位置和阅读顺序信息。
2. 对图片为主体、文字层缺失或文字层不可信的页面，沿用页面渲染与 OvisOCR2 识别流程。
3. 对混合 PDF 按页分流；必要时允许在单页内采用原生文字与视觉区域 OCR/裁图相结合的处理方式。
4. 在不降低内容忠实度的前提下，显著降低文字型 PDF 的首结果等待时间、总耗时和资源消耗。
5. 在结构化结果、Markdown、进度、checkpoint 和 `result.json` 中提供可审计的分类、处理方式、依据和回退信息。

### 2.2 成功定义

- 用户继续使用 `ocrx scan <PDF>`，默认即可获得自动分流能力，无需理解 PDF 内部结构。
- 纯文字型 PDF 的成功处理不依赖 OvisOCR2 已安装，也不触发模型下载或初始化。
- 图片型 PDF 的现有 OCR 能力和输出质量不退化。
- 混合 PDF 不因少量文字页或扫描页而被整本错误地固定到单一路径。
- 自动分类不确定或直接提取质量不合格时，系统保守回退到 OCR，并明确记录原因。

## 3. 范围与非目标

### 3.1 本期范围

- 分析 PDF 页面中的文字对象、图片对象、页面覆盖关系及文字可用性。
- 形成文档级分类摘要和页面级处理决策。
- 从原生 PDF 提取 Unicode 文字、字符/文字块位置及可可靠恢复的格式角色。
- 将原生提取结果规范化为 OCRX 统一页面文档。
- 对图片页执行现有全页 OCR；对混合页支持阶段化交付的处理策略。
- 自动回退、显式模式覆盖、进度事件、结果报告、恢复与测试契约。

### 3.2 非目标

- 精确复刻 PDF 的字体文件、字距、颜色、坐标排版或生成视觉上一致的 HTML/Word。
- 编辑、修复或回写 PDF 文字层。
- 绕过 PDF 权限、密码或加密限制。
- 将不可见 OCR 文字层直接视为正确真值。
- 首期承诺对所有复杂矢量图、数学公式、表格和任意编码字体进行无损语义还原。
- 使用大语言模型修正、总结、翻译或补全文字层内容。

## 4. 核心原则

### 4.1 页面级路由优先

文档级类型用于汇总和用户解释，真正的执行决策以页面为单位。页面分类至少包含：

| 页面类型 | 含义 | 默认路径 |
| --- | --- | --- |
| `text` | 可靠、可读的原生文字覆盖页面主要信息 | 原生提取 |
| `image` | 页面信息主要存在于栅格图像中，或文字层不可用 | 全页 OCR |
| `mixed` | 原生文字和重要图像内容并存，任一来源都不能独立完整表达页面 | 混合处理；能力不足时全页 OCR |
| `empty` | 页面无可见内容或仅有可忽略装饰 | 生成空页面结果并记录 |
| `uncertain` | 证据冲突或置信度不足 | 保守回退全页 OCR |

文档级类型根据所选页面的分类汇总为 `text`、`image`、`mixed` 或 `empty`。只要有效页面使用了多种主要处理路径，文档即应汇总为 `mixed`，不得用多数票隐藏少数扫描页。

### 4.2 可见页面是内容依据

PDF 文字对象是高质量提取来源，但不是天然可信的真值。隐藏文字、错误编码、与页面图像错位的扫描 OCR 层、重复文字、乱码、仅用于搜索的不可见文本均可能存在。分类器必须结合文字可见性、Unicode 可解码性、几何位置、重复程度、页面覆盖率和图片覆盖情况评估其可靠性。

系统不得仅以“页面存在文字对象”作为走直接提取路径的条件。

### 4.3 统一输出、来源可追溯

直接提取和 OCR 都必须生成同一版本的 `PageDocument`。下游 Markdown、图片资产、评分、checkpoint 和 Agent 调用不得依赖处理引擎的私有格式。每个页面和内容块应保留来源信息，以区分 `pdf_text`、`ocr`、`pdf_object` 和后续可能的合并结果。

## 5. 用户体验与 CLI

### 5.1 默认行为

```bash
ocrx scan document.pdf
```

默认使用 `--pdf-mode auto`：先进行轻量 PDF 分析，再按页选择处理路径。分析阶段不得初始化或下载 OCR 模型；只有至少一个待处理页面需要 OCR 时，才进入模型推荐、安装/离线校验与初始化流程。

默认要求的内容能力层为《质量分层与 Profile 要求标准》中的 L2。用户显式只要求 L1 时，原生路径应按 L1 准入和校验，不得因缺少仅属于 L2 的结构而启动 OCR。质量能力层与模型 profile 是两个独立概念；`--model-profile quality` 等参数不得被解释为 L1/L2/L3 请求。

### 5.2 模式控制

新增参数：

```text
--pdf-mode <auto|text|ocr>
```

| 值 | 行为 |
| --- | --- |
| `auto` | 默认。分析后逐页路由，低置信度页回退 OCR。 |
| `text` | 强制只使用原生提取；任何选中页面不满足最低可用条件时任务失败，不静默 OCR。适合禁止加载模型的确定性流程。 |
| `ocr` | 强制沿用全页渲染与 OCR，不使用文字层生成正文。适合质量对比、异常 PDF 和回归。 |

`--offline` 不应阻止文字型 PDF 处理。仅当实际路由到 OCR 且本地缺少所需模型时，才返回离线缺模型错误。

### 5.3 要求的质量层级

新增参数：

```text
--quality-tier <l1|l2>
```

| 值 | 行为 |
| --- | --- |
| `l1` | 文字忠实层。要求可见文字和页面事实忠实、无遗漏/增生/改写，并保持自然阅读顺序；不因标题层级、列表嵌套、block 角色、方向元数据或脚注关系等仅属于 L2/L3 的字段无法恢复而启动 OCR。 |
| `l2` | 默认。块级结构层。除 L1 外，还要求恢复本需求第 7.2 节规定的 block、角色、位置、方向和阅读顺序。 |

P0 不接受 `l3` 作为已支持的原生提取承诺；传入未支持的层级必须在 PDF 分析、模型检查和输出写入前返回参数错误。后续支持 L3 时另行定义，不在本需求范围内。

任务的 `required_quality_tier` 必须在开始分析前确定，并对本次任务的所有选中页面保持一致。未显式指定时为 `l2`。页面是否需要 OCR、原生提取后是否回退，以及最终质量报告，均以该有效层级为判断依据。

模式与质量层级组合规则如下：

| 组合 | 不满足要求层级时的行为 |
| --- | --- |
| `auto + l1/l2` | 当前页回退全页 OCR。 |
| `text + l1/l2` | 当前页明确失败，不得启动 OCR。 |
| `ocr + l1/l2` | 仍强制全页 OCR；层级用于结果验收和报告，不改变执行路径。 |

### 5.3 用户可见反馈

- 分析完成后显示文档分类及页面计划，例如：`18 text, 2 image, 1 mixed`。
- 进度必须区分 `analyzing`、`extracting`、`rendering`、`recognizing`、`merging` 阶段。
- 普通文本报告应显示实际使用的处理路径、OCR 页数、回退页数和主要警告。
- JSON/JSONL 模式必须使用稳定枚举和字段，不要求消费方解析日志文本。

## 6. PDF 分析与分类需求

### 6.1 分析输入

每个选中页面至少采集下列信号：

- 页面尺寸、旋转角度和裁切框。
- 文字对象数量、可见字符数、有效 Unicode 比例、控制字符/替代字符/乱码比例。
- 文字块 bbox、字符 bbox、文字覆盖区域、字体大小分布和渲染模式；不可见、透明、裁切区外文字单独计数。
- 栅格图片数量、bbox、像素尺寸、页面覆盖率；识别接近全页的背景扫描图。
- 文字与大图的空间重叠，用于识别“扫描图 + 隐藏 OCR 层”。
- 重复文字、异常密集叠字、字符位置集中在零面积或页面外等可疑特征。
- 页面是否只有矢量路径、公式字形、轮廓化文字或不具备可靠 Unicode 映射的字体。

实现可以增加其他确定性信号，但不得依赖联网服务或在分析阶段调用 OvisOCR2。

### 6.2 分类规则

分类器必须是可版本化、可测试的确定性组件，并输出：

- `page_type`
- `confidence`（`high`、`medium`、`low`）
- `recommended_method`
- 命中的 reason code 列表
- 关键统计值
- 分类器规则版本

首个实现的阈值必须通过代表性样本校准后冻结在版本控制配置中，不在本需求中伪造固定数值。至少应遵循以下决策原则：

1. 有足量可见、有效、分布合理的 Unicode 文字，且不存在主导页面的扫描大图时，候选为 `text`。
2. 缺少有效文字，而一个或多个图片覆盖页面主要内容区域时，候选为 `image`。
3. 大图覆盖页面且存在高度重叠的文字层时，先判定文字层是否为可信的扫描 OCR 层；未经验证不得直接提取。
4. 可靠原生正文与承载重要可读信息的图片区域并存时，判定为 `mixed`。
5. 乱码率、不可见文字比例、异常重复或几何异常超过安全阈值时，标记 `uncertain` 或 `text_layer_unreliable`，默认 OCR。
6. 单页短内容（封面、章节页、单个页码）不得只因字符数少就判为图片页；应结合图片和布局信号。

### 6.3 全量分析与抽样

自动模式必须为所有用户选中的页面形成决策，不得仅抽样后把整本文档固定为同一类型。实现可用抽样生成早期文档摘要，但执行某页前必须完成该页分析。

## 7. 原生文字提取需求

### 7.1 内容忠实性

- 提取逻辑 Unicode，不得自动纠错、翻译、改写或补全。
- 正确处理页面旋转、字符方向、连字、组合字符、软连字符和跨行断词；无法无损判断时保留原始事实并产生 warning。
- 去除 PDF 绘制指令造成的同位置重复文字，但不得用模糊去重误删正常重复内容。
- 不可见文字默认不进入正文；其存在可作为诊断信息记录。
- 若字体缺少可靠 Unicode 映射或提取结果为乱码，页面必须回退 OCR，而不是输出损坏文本。

### 7.2 结构与格式

P0 默认能力和发布必达能力冻结为《质量分层与 Profile 要求标准》中的 **L2：块级结构层**。当有效质量层级为 L2 时，直接提取必须利用文字位置、字体属性和页面对象恢复：

- 自然阅读顺序和多栏布局。
- 标题、段落、列表、引用、代码/预格式文本、页眉、页脚、页码和脚注等 block。
- 文字 block 的 bbox、方向、旋转角度和来源。
- 原始编号、项目符号、复选状态、列表项目边界和层级。

L3 能力，包括行内文字 run 的粗体、斜体、删除线、上标、下标和链接语义，视觉对象与附属文字关系、脚注/引用关联，不是 P0 原生提取路径的发布必达项，归入 P1。P0 可以输出其中能够可靠确定的字段，但错误的高阶字段视为质量失败；不确定时应留空，不得猜测。

字体名或字号只能作为结构证据，不能单独证明语义角色。当有效质量层级为 L2，若页面不能可靠恢复多栏阅读顺序、block 边界、文字方向或列表结构，则该页不得以 `native_text` 作为最终处理方式：`auto` 模式必须回退 OCR，`text` 模式必须明确失败。

当用户显式要求 L1 时，原生路径准入只要求满足 L1：可见文字和页面事实忠实，无遗漏、增生、改写或错误替换，并能按自然阅读顺序输出。仅有以下 L2 结构缺失不得触发 OCR：标题/正文角色不确定、列表嵌套不确定、页眉页脚/脚注角色不确定、block 边界只能粗粒度恢复，或方向/旋转元数据无法完整提供；这些字段应留空或使用不臆造语义的粗粒度 block。

L1 仍不得放行不可信文字层。乱码、缺字、异常重复、隐藏或错位文字层、无基本阅读顺序、可见文字位于图片中但原生文字层未覆盖，或其他导致页面可读文字/页面事实不完整的情况，仍须在 `auto` 下 OCR、在 `text` 下失败。普通文本表格或公式若能忠实保留全部可见字符及自然阅读顺序，可以按 L1 原生输出而不要求恢复表格结构或 LaTeX；若这种粗粒度输出会改变事实、混淆顺序或遗漏可读内容，则仍不满足 L1。

### 7.3 表格、公式和视觉对象

- 原生 PDF 中的普通文本表格可以依据几何关系恢复为结构化表格；未达到可靠阈值时保留按阅读顺序组织的文字块，并记录 `table_structure_unresolved`。
- 可映射为 Unicode/数学语义的公式应进入公式 block；仅由分散字形或矢量轮廓组成、无法可靠重建的公式不得伪造 LaTeX。
- 重要图表、插图、二维码和条码仍作为视觉对象保存。直接提取正文不代表可以丢弃页面中的非文字信息。
- 若文字页含无法由原生对象完整表达的重要视觉内容，可升级为 `mixed`；当前版本不具备可靠区域级识别时，整页回退 OCR。

P0 不要求原生提取路径实现公式 LaTeX、HTML 表格和完整视觉对象关系。页面包含公式、表格或重要视觉内容时，只有在现有提取能力能够满足任务有效质量层级后，才允许最终使用 `native_text`：L1 可以不恢复表格/公式结构，但必须忠实保留全部可见字符、页面事实和自然阅读顺序；L2 必须满足对应的块级结构要求。任一必达内容不能满足时，必须分类为 `mixed`/`uncertain` 或在提取后回退 OCR。不得为了提高原生提取页比例而输出不满足有效层级的降级文本。

## 8. 图片页与混合页处理

### 8.1 图片页

图片页使用既有路径：按约定 DPI 渲染、适配模型像素预算、OvisOCR2 推理、adapter 解析、视觉区域裁图并写入统一页面文档。

### 8.2 混合页交付阶段

为了先保证正确性，混合处理分两阶段：

**阶段 A（最低可交付）**

- `text` 页直接提取。
- `image`、`mixed`、`uncertain` 页执行全页 OCR。
- 已能覆盖文档内按页混合的常见场景，且不引入跨来源去重风险。

**阶段 B（增强能力）**

- 同一页面内使用可靠原生文字作为正文，仅对重要图片区域进行 OCR/视觉理解。
- 合并时按页面坐标和阅读顺序组织 block，检测重叠内容，避免原生文字与 OCR 文字重复。
- 任一区域边界、阅读顺序或去重置信度不足时，整页回退 OCR。

阶段 B 不得阻断阶段 A 发布；其独立验收标准满足后才能默认启用。

## 9. 质量保护与运行时回退

### 9.1 提取后校验

原生提取完成后必须执行页面级校验，至少检查：

- 输出是否为空或主要为乱码/控制字符。
- 输出字符数与分析阶段可见字符统计是否显著不一致。
- 是否出现大面积页面内容无对应 block、异常重复或重叠。
- block bbox 是否有效且位于页面范围内。
- 阅读顺序是否可形成稳定序列。

校验必须按任务的 `required_quality_tier` 执行。L1 校验只把文字忠实、页面事实完整和自然阅读顺序作为必达项，不得因仅属于 L2 的结构字段缺失而失败；L2 校验同时执行第 7.2 节的 block 结构要求。校验失败时，`auto` 模式将该页重新路由到 OCR，并记录 `extraction_fallback` 及 reason code；`text` 模式则将页面标记失败，不允许偷偷改变执行方式。

### 9.2 OCR 不可用时的行为

若 `auto` 判定部分页面需要 OCR，但运行环境无法加载模型：

- 不得把这些页面强行按文字提取后宣称成功。
- 已完成的文字页可以保留为 checkpoint。
- 任务按既有失败策略返回 `partial` 或失败状态，并准确列出未处理页面。
- `--resume` 在模型可用后只处理尚未完成或已失败页面。

## 10. 统一数据与输出契约

### 10.1 页面结果

`PageDocument` 应增加或等价表达：

```json
{
  "page_number": 1,
  "classification": {
    "type": "text",
    "confidence": "high",
    "reasons": ["visible_unicode_text", "no_dominant_scan_image"],
    "classifier_version": "pdf-route-v1"
  },
  "processing": {
    "planned_method": "native_text",
    "actual_method": "native_text",
    "fallback_from": null,
    "fallback_reason": null
  },
  "blocks": []
}
```

每个 block 至少带有稳定来源枚举：`pdf_text`、`pdf_image`、`ocr` 或 `derived`。若 block 来自合并，还应能追溯对应源对象或 OCR 区域。

### 10.2 `result.json`

增加或等价表达：

- `document_classification`
- `pdf_mode`
- `required_quality_tier`
- `classifier_version`
- `page_type_counts`
- `processing_method_counts`
- `ocr_model_loaded`
- `fallback_page_count` 和逐页原因
- 每页分类、计划方式、实际方式、耗时和 warning
- 分析、原生提取、渲染、OCR、合并各阶段耗时

模型相关字段在纯原生提取任务中必须允许为空，不得伪造 OvisOCR2 revision/profile。

### 10.3 Markdown 与资产

- 两种路径继续生成同一个 `document.md`，页面分隔规则保持不变。
- 默认 Markdown 不插入“本页由 PDF 提取/OCR 生成”等噪声；来源信息保存在结构化结果和报告中。
- 图片资产命名、引用和 bbox 坐标规范在两条路径中保持一致。
- 相同输入、页码选择、模式、分类器版本和提取器版本应产生确定性结果。

## 11. Checkpoint、恢复与兼容性

- checkpoint 兼容键新增 `pdf_mode`、`required_quality_tier`、分类器版本、原生提取器版本、页面分类和实际处理方式。
- 更改强制模式、分类规则版本或影响输出的提取规则时，不得错误复用不兼容页面结果。
- OCR 模型 revision/profile 只影响实际使用 OCR 的页面；纯原生提取页面不应因本地模型变化而失效。
- `--resume` 必须能够复用已校验的文字页，同时继续处理需要 OCR 的页面。
- 统一文档 schema 升级必须提供旧 checkpoint 的明确拒绝或迁移策略，不得静默误读。

## 13. 性能与资源要求

- PDF 分析逐页执行，不一次性加载整本文档的所有页面对象或位图。
- 纯文字型 PDF 不渲染全页高 DPI 位图，不初始化 llama.cpp/MTMD，不加载或下载模型。
- 只在提取视觉资产或校验确有需要时进行局部或低成本渲染；不得让分类预检退化为完整 OCR 成本。
- 混合文档只为实际 OCR 页面进行高 DPI 渲染和模型推理。
- 处理 100 页文字型 PDF 时内存不得随页数线性增长。
- 发布前必须以固定基准报告纯文字、纯扫描和混合 PDF 的分析耗时、总耗时、峰值 RSS、模型是否加载及输出大小。
- 在第 14.1 节完整的“原生文字合格集”、同一台发布基准机器、冷启动且重复至少 5 次的条件下，`auto` 必须在每次测量中将全部页面最终交付为 `native_text`；任一页面回退、使用 OCR 或失败时，该次运行和整个性能验收均判定失败，不得只对成功直接提取的页面计时。满足此前提后，任务总耗时中位数必须不高于 `--pdf-mode ocr --model-profile quality` 处理同一完整集合时的 `50%`，且不得发生模型初始化或模型文件读取。报告必须同时给出绝对耗时和各次测量值。
- 性能门槛只用于证明原生路径提高处理效率，不得抵消第 14.3 节的任何质量门槛；质量未通过时，即使速度达标也不得发布。

## 14. 测试集与验收

### 14.1 必备样本

测试集至少覆盖：

- 正常原生中文、英文及中英混排 PDF。
- 单栏、多栏、页眉页脚、脚注、列表、链接、粗斜体、上下标。
- 原生表格、公式、嵌入图片和矢量图。
- 无文字层扫描件。
- 扫描图加可靠隐藏 OCR 层、错误 OCR 层、错位文字层和重复文字层。
- 字体编码损坏、缺少 ToUnicode、乱码、轮廓化文字。
- 同一文档中原生页与扫描页交替出现。
- 单页内文字与重要图片内容混合。
- 空白页、封面短文本页、旋转页、不同页面尺寸。
- 加密、损坏、超长和页数较多的 PDF。

所有分类样本必须有人审阅的页面类型、允许路径和内容真值；分类器阈值不能只针对合成 fixture 调优。

P0 必须从上述样本中冻结两个互不替代的页级集合：

1. **原生文字合格集**：至少 30 页，包含中文、英文、中英混排、单栏、多栏、标题、段落、列表、页眉页脚、脚注、旋转文字和不同页面尺寸；每页均具有人工校对的逻辑文字、L2 block、阅读顺序、方向和 bbox 真值。每页的人工预期类型必须冻结为 `text`，预期最终处理方式必须冻结为 `native_text`。该集合用于同时验证应直接提取页面的路由覆盖率和原生提取质量，不允许实现自行从评分集合中排除困难页面。
2. **不得直接提取集**：至少 20 页，覆盖无文字层扫描件、错误或错位隐藏 OCR 层、乱码、缺少可靠 Unicode 映射、重复/不可见文字、轮廓化文字，以及 P0 无法完整表达的公式、表格或重要视觉内容。该集合用于验证错误放行和 OCR 回退。

样本页不得同时出现在两个集合中。集合、源 PDF 哈希、页码、人工真值、分类标签、评分脚本和版本必须随发布冻结；更换任一项均形成新的基准版本，旧分数不得混算。

“原生文字合格集”的纳入由人工依据页面可见内容和 PDF 对象可用性在实现验收前完成，不得根据待测实现是否成功、是否回退或得分高低事后调整。需要 P1/P2 能力才能完整表达的公式、表格或重要视觉页面不得放入该集合，应进入“不得直接提取集”或对应后续阶段的独立集合。

### 14.2 功能验收

1. `auto` 能为每个选中页面输出分类、依据和实际处理方式。
2. 纯文字 PDF 全程不加载/下载 OCR 模型，且在未安装模型和 `--offline` 下成功。
3. 纯扫描 PDF 路由到 OCR，输出能力不低于现有基线。
4. 页级混合 PDF 仅对需要的页面执行 OCR，并按原页码正确合并。
5. 不可信文字层不会仅因“存在文字”而绕过 OCR。
6. 原生提取后校验失败能在 `auto` 下回退，并在 `text` 下明确失败。
7. `--pdf-mode ocr` 可复现既有全页 OCR 行为，支持质量对照。
8. `--resume` 可跨“文字页已完成、OCR 页待处理”的中断恢复。
9. Markdown、图片引用、结构化结果和报告中的页码、阅读顺序及来源一致。
10. Agent 可仅依据 `result.json` 判断任务是否纯提取、是否使用模型、哪些页回退或失败。
11. 在完整“原生文字合格集”上运行 `auto` 时，所有页面必须最终采用 `native_text`，不得加载 OCR 模型；任一页面回退、失败或改用 OCR 都必须使 P0 验收失败。
12. 显式使用 `--quality-tier l1` 时，仅缺少 L2 block 角色、边界、层级或方向元数据的可信文字页仍采用 `native_text`；存在乱码、遗漏、重复、错位文字层或基本阅读顺序错误的页面仍不得直接交付。
13. 相同页面分别以 L1、L2 运行时，若其文字忠实但 L2 结构不可恢复，`auto + l1` 必须原生成功，`auto + l2` 必须回退 OCR；`text + l2` 必须失败且不启动 OCR。

### 14.3 质量验收

#### 14.3.1 P0 能力层与评分对象

- P0 原生提取路径按 **L2：块级结构层**验收；L1 是所有页面必须满足的底线，L3 不作为 P0 发布门槛。
- 本节固定发布门禁统一使用默认 `--quality-tier l2`。允许用户请求 L1 不改变原生文字合格集的 L2 真值、100% 原生路由覆盖率或任何 L2 发布阈值，也不得用 L1 运行结果替代本节评分。
- 评分对象是第 14.1 节完整的“原生文字合格集”，评分分母固定为该集合冻结的全部页面和全部对应真值，不得只计算最终实际处理方式为 `native_text` 的子集。PDF 隐藏文字层只作为输入，不作为真值；评分必须使用人工依据可见页面建立的真值。
- P0 评分使用 `requirements-v0.1.md` 第 17.2.2 节相同的 Unicode NFC、换行和行尾空白归一化规则，以及相同的文本 NED、阅读顺序准确率定义。
- block 评分对真值与结果按类型和归一化逻辑文字进行一对一最优匹配。匹配成功的输出 block 数 / 全部输出 block 数为 block precision；匹配成功的真值 block 数 / 全部真值 block 数为 block recall；两者调和平均为 block F1。一个真值 block 被错误拆成多个输出 block、多个真值 block 被错误合并，或 block 类型错误，均不得视为完整匹配。
- bbox 有效率沿用 v0.1 定义。文字 block bbox 召回率按与真值 bbox 的 IoU `>= 0.5` 一对一匹配计算。不同方向文字的方向和旋转角度必须与真值一致，否则对应 block 不计为匹配。

#### 14.3.2 P0 原生提取发布门槛

在第 14.1 节“原生文字合格集”上，以下条件为 **AND** 关系，任一项不满足即 P0 原生提取路径不通过：

| 指标 | 发布门槛 |
| --- | ---: |
| `auto` 最终采用 `native_text` 的页面数 | `全部页面` |
| 原生路由覆盖率 | `100%` |
| 回退、OCR 或失败页面 | `0` |
| 文本 NED | `>= 0.99` |
| 阅读顺序准确率 | `>= 0.98` |
| block precision | `>= 0.97` |
| block recall | `>= 0.97` |
| block F1 | `>= 0.97` |
| 文字 block bbox 有效率 | `>= 0.99` |
| 文字 block bbox 召回率 | `>= 0.97` |
| 非原文重复输出页面 | `0` |
| 空白或失败页面 | `0` |

原生路由覆盖率按“最终实际处理方式为 `native_text` 的合格集页面数 / 合格集全部页面数”计算。任何被分类为其他类型、回退 OCR、处理失败或缺少结果的页面均计为未覆盖，并直接导致 `100%` 门槛失败；不得将其从文本、block、bbox 或阅读顺序指标的分母中删除。若任一指标没有有效分母，整个验收结果必须判定为失败，不得报告为 `N/A` 或通过。

同时，对同一完整集合运行 `--pdf-mode ocr --model-profile quality` 作为对照。原生提取的文本 NED 不得低于该 OCR 对照超过 `0.005`，阅读顺序准确率不得低于该对照超过 `0.01`。绝对门槛与相对门槛必须同时满足。OCR 对照用于防止新路径相对现有生产能力明显退化，不改变原生路径独立于模型 profile 的绝对门槛。

#### 14.3.3 分流与回退发布门槛

在第 14.1 节“不得直接提取集”上：

- `auto` 模式下最终以 `native_text` 成功交付的页面数必须为 `0`。页面可以在分析阶段成为候选，但提取后校验必须在交付前将其回退 OCR。
- 需要 OCR 且模型可用时，页面必须实际进入 OCR；模型不可用时必须按第 9.2 节失败或返回 `partial`，不得降级为原生文字成功。
- `text` 模式必须明确失败，不得静默 OCR，也不得将不完整纯文本标为成功。
- 分类报告必须给出混淆矩阵、逐页计划方式、实际方式、回退原因和错误页面清单。

上述“错误放行数为 0”是 P0 高风险门禁，不得以总体准确率、原生提取覆盖率或性能收益抵消。低置信度必须偏向 OCR。

#### 14.3.4 P1/P2 边界

- P1 增加的 L3 格式、公式、表格、链接、图片和关系能力必须在启用对应原生输出前另行冻结专项指标与门槛；未达到门槛的页面继续回退 OCR，不阻断 P0 发布。
- P2 区域级混合处理必须独立验证跨来源重复、区域召回和阅读顺序；其门槛未通过前不得默认启用，也不影响阶段 A 的 P0 判定。
- 不允许用 P1/P2 尚未实现作为降低 P0 L2、错误放行或内容完整性门槛的理由。

## 15. 可观测性与隐私

- 默认不上传 PDF、提取文字、页面图片、分类统计或模型结果。
- debug 日志不得输出整页正文；可记录计数、比例、reason code、页码和版本。
- `--report json` 的 stdout 纪律保持不变，所有进度和日志写入既有规定的通道。
- 分类和回退决策必须可从本地 checkpoint/`result.json` 复盘，不依赖临时日志。

## 16. 实施优先级

### P0：安全的页级双路径

- PDF 页面分析器与版本化分类结果。
- `auto|text|ocr` 模式与 `l1|l2` 有效质量层级。
- 原生文字、位置和 L2 块级结构提取到统一页面文档。
- `text` 页直接提取；其余页全页 OCR。
- 提取后校验、回退、checkpoint、报告及离线行为。
- 覆盖不可信隐藏文字层的回归集和质量/性能基准。
- 满足第 14.3 节的 L2 数值门槛和不得直接提取集零错误放行门禁。

### P1：原生结构增强

- 多栏阅读顺序、标题/列表/页眉页脚/脚注识别增强。
- 原生表格、公式、链接和嵌入图片的可靠提取。
- 更完整的格式 run 和页面对象来源追踪。

### P2：单页区域级混合

- 重要视觉区域识别与局部 OCR。
- 跨来源 block 合并、空间阅读顺序和重复消解。
- 区域级失败回退及独立质量门禁。

## 17. 待技术验证但不改变的产品决策

以下实现细节需在技术设计和基准阶段确定：

1. 现有 PDFium binding 对字符级 Unicode、可见性、字体属性、图片对象和渲染模式的覆盖程度；不足时采用何种可再分发组件补足。
2. 分类信号的具体阈值、权重和置信度校准方法。
3. 阅读顺序、段落合并、重复文字层识别和断词处理算法。
4. 原生图片提取与页面裁切之间的选择规则。
5. 表格、公式结构无法可靠恢复时，进入 P1 解析器还是直接升级为 OCR 的边界。

无论采用何种实现，以下产品决策已经固定：按页判断、低置信度偏向 OCR、纯文字任务不加载模型、两条路径进入统一结构、所有决策可追溯、用户可以强制选择模式。

## 18. 与现有需求的关系

本需求扩展 `docs/requirement/requirements-v0.1.md` 的 PDF 逐页处理章节。原有“所有页面渲染并送入 OvisOCR2”调整为图片页和回退页的处理路径；既有 OvisOCR2、Markdown、裁图、checkpoint、进度、错误码和 Agent 输出契约继续适用于实际 OCR 页面。

如两份文档存在冲突，本需求在 PDF 内容分类、原生提取、延迟模型加载和逐页路由范围内优先；其他产品边界仍以 v0.1 总需求及 `docs/quality-standards/` 下的质量标准为准。
