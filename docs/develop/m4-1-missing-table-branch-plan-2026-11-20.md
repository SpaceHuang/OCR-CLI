# M4.1 缺失表格分支开发计划（2026-11-20）

**状态：** 草案 v1.0（待评审）
**数据依据：** `benchmarks/omnidocbench/reports/analysis/analysis-lesion-attribution-ovisocr3.json`（OvisOCR3 默认基线的 <0.5 病灶归因）——53 张 0 分表格中 **32 张模型未输出任何 `<table>` 块**（内容退化为纯文本）、21 张结构错配；**53/53 页面均被 sidecar 表格区域检出**（97.3% 召回的 PP-DocLayoutV2 完全覆盖）；54 张 <0.5 慢性表中双模型取优 oracle 仅 0.154（换模型无空间）。
**关联计划：** `m4-table-reopen-development-plan-2026-11-16.md`（v1.6，管线基础设施全部复用）；`ovisocr3-default-switch-plan-2026-11-18.md`（当前基线 = OvisOCR3，Overall 90.87）。
**方案性质：** M4 管线的**增量分支**（F6 触发），不推翻已判 NO-GO 的 M4 主体（已输出表格的重读人群）——两个人群互斥，证据独立。

## 1. 机制缺陷（为什么这是新方向而不是旧 M4 复活）

M4 触发器 F1–F5 全部作用于**已输出的表格 HTML 块**。0 分表的失败模式是**页面根本没有表格块**（模型把表格内容当普通文本输出）——触发器在这类页面**结构性永不触发**，重读管线永远够不到。这不是"重读无增益"（B2 战役的 Δ≈0 结论测的是已输出表格的人群），而是**管线覆盖不到**。

区域信号完全现成：sidecar（PP-DocLayoutV2，route A）在 53/53 的 0 分页面上检出表格区域。缺失的只是触发分支与替换规则。

## 2. 目标人群与杠杆

| 人群 | 规模 | 现状 | 修复价值 |
|---|---|---|---|
| 主目标：0 分表（≤TEDS 0.0） | 53 | 预测无表格块 32 + 结构错配 21 | 全部修复到全集表格均值（0.86）≈ **+2.9 Overall** |
| 次目标：0.05–0.5 低分表 | 45 | 部分结构错误 | 逐样本归因后再定 |
| 已输出表格的重读（旧 M4 人群） | — | B2 判 Δ≈0 | **不在本计划范围**（证据仍为 NO-GO） |

## 3. 决策

| ID | 决策 | 理由 |
|---|---|---|
| D-53 | 新增触发分支 **F6（缺失表格）**：sidecar 检出表格区域，但输出页面中**无对应表格块**（无任何 `<table>`，或表格块数 < 检出表格区域数）→ 对缺失/错配的区域执行裁剪重读 | 人群 53/53 被区域信号覆盖；F1–F5 结构性够不到；管线其余环节全部复用 |
| D-54 | **无基线替换规则**：F6 重读产出的表格**不直接替换**——先过结构有效性门（可解析为表格 + 行×列 ≥ 2×2 + 非全空），过门后**直接采用**（无原表可比，比较保留失去意义）；未过门 → 保原（文本形式） | F6 人群没有"原表"可比较——compare-keep 无基线。直接采用的风险由结构有效性门 + B2 门③（good 带回归防护）+ 抽样人工复核三重后盾；未过门保原 = 失败模式与 M4 相同（不替换无损失） |
| D-55 | F6 仅在 `--table-reread on` 下生效，与 F1–F5 同一开关同一身份字段（`reread_rules_generation` 不变——F6 是新增分支而非规则修改；但**实现上 F6 引入新的触发输入（区域-输出对比），代次 +1 以区分行为**） | 开关/身份面最小化；代次 +1 保证 resume 不混用 |
| D-56 | F6 的配对规则：输出表格块与检出区域按**既有序数配对**（复用 pairing 逻辑）；检出区域多于输出块时，**多出的区域**逐个裁剪重读 | 多表页部分输出的场景（检出 2 区域、输出 1 块）天然覆盖 |
| D-57 | 范围 = 表格；公式不纳入 F6（B0' 公式检测门 ~60% 未过，无合格区域信号；M5 维持关闭，重开条款不变） | 公式区域来源仍未解决；表格区域 53/53 覆盖 |

## 4. 任务分解

| 任务 | 内容 | 验收 |
|---|---|---|
| T1 | F6 触发实现：`reread.rs` 编排增加"检出区域 vs 输出表格块"计数对比分支；缺失区域走既有 crop → decode 链 | 单测：检出 2 区域输出 0 块 → 2 次裁剪重读；检出 2 输出 1 → 1 次重读；全配对 → 零次 |
| T2 | 结构有效性门 + 直接采用规则（D-54）：可解析、≥2×2、非全空；未过门保原并计 `f6_rejected` | 单测：有效 HTML 采用/不可解析保原/全空保原 |
| T3 | 计数器与 result 面：`f6_triggered/f6_replaced/f6_rejected` 入 RereadStats 与 result.json | 单测 + golden 更新 |
| T4 | 53 页冻结人群 spike：`--table-reread on` 跑 53 页（现配置 OvisOCR3），人工抽验 10 张替换结果 + 官方 TEDS 逐表 | **spike 判据（预注册）**：替换表中 TEDS ≥ 0.5 的比例 ≥ 60% 且无好表回归（F6 只动零/低分表，理论上无回归面）；未达 → 停止，归因后议 |
| T5 | T4 过线 → B2 五门适配版战役（人群改为 53 页 + 全集回归防护）→ 判定转正与否 | 与 M4 同构的门禁纪律 |

## 5. 风险与边界

| 风险 | 缓解 |
|---|---|
| 无基线替换引入垃圾表（fail-open 面） | D-54 结构有效性门 + T4 人工抽验 + B2 门③复用；替换率可观测（f6_rejected 计数） |
| F6 与 F1–F5 在同一页面同时触发 | 配对逻辑天然互斥：F1–F5 消费已配对的块，F6 只消费**未匹配的区域**；编排顺序冻结 |
| 检测区域是误检（非表格内容） | 重读输出过不了结构有效性门 → 保原；误检率由 97.3% 精确率背书 |
| 表格跨页/区域框不全 | 与 M4 既有约束相同（v1 不解，人群外样本保原） |

## 6. 明确不做

- 已输出表格的重读规则修改（旧 M4 人群维持 NO-GO 证据）
- 公式 F6（D-57）
- 双模型路由（另立计划）
- M5/M6b 重开

## 成本估算

T1–T3：约 1 个工程日（管线全复用，新代码 = 触发分支 + 有效性门 + 计数器）；T4：53 页扫描 ≈ 30 分钟 + 人工抽验 1 小时；T5：视 T4 结果。
