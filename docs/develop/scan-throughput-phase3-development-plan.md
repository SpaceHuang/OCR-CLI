## 0. 现状与问题定位

### 0.1 二期落点与残余瓶颈

| 场景 | 现状 | 窗口解码占每文档 | 非窗口占每文档 |
|---|---:|---:|---:|
| 金集单文档（30 页，depth 8） | 34.02 s | 24.3 s（71%） | ≈9.7 s（≈0.32 s/页） |
| md-small-20 编排（20×2 页图像文档） | 114.2 s（1.35× vs 逐个调用） | ≈1.0 s（18%） | **≈4.6 s（82%）** |

二期 X1.4④ 的结论：编排的固定税摊薄（2.1 s/文档）已完全兑现，剩余瓶颈是**每文档 ≈4 s 的"渲染 + 全页 PNG 编码 + 提交"串行段**——它既不在 GPU 上，也不在推理 actor 上，是纯 host 串行成本。

### 0.2 提交段构成（推断，待 T1 实测钉死）

| 子项 | 估计量级 | 依据 |
|---|---:|---|
| **全页 PNG 编码**（`page-NNNN.png`） | ≈1.5–2 s/页（图像页最坏情形） | `image` crate 默认 deflate 编码 ~8MP 照片型 RGB（≈24 MB 像素，压缩比差）；金集文本页 ≈0.2–0.3 s/页（留白多压缩快）——**成本强内容依赖** |
| PDFium 渲染 | ≈0.2–0.5 s/页 | 已被 owner 线程 K=2 预取与上一窗解码部分重叠（一期 P3） |
| 落盘/收尾 | <0.5 s/文档 | atomic write、checkpoint、document.md finalize |

**结构性发现（杠杆 P3 的依据）**：`commit_page` 写下的全页 `page-NNNN.png` 在文档成功后被 `cleanup_full_page_images` **删除**（`--keep-pages` 除外）。默认路径下它是"编码 2 s、写完即弃"的过路文件；`--resume` 只依赖 checkpoint + `page-*.md`，无任何恢复路径读取它。

### 0.3 关键观察（杠杆 P2 的依据）

`PageArtifactResult.png` 只依赖渲染结果（`RenderedPage.rgb8`），**不依赖识别输出**——编码可以在该页渲染完成时立即开始，与同窗 GPU 解码完全并行。当前实现把编码串在解码之后（窗口解析 → 逐页编码），纯调度损失。

## 1. 目标与非目标

### 1.1 目标

| 口径 | 现状 | 主目标 | 冲刺 |
|---|---:|---:|---:|
| md-small-20 编排墙钟（20×2 页图像文档） | 114.2 s | **≤85 s（≈1.9× vs 逐个调用基线 155 s）** | ≤60 s（≈2.6×） |
| 金集单文档墙钟（解码主导，收益较小） | 34.02 s | ≤32 s | ≤31 s |
| 产物契约 | 逐字节门禁集合不变（P1/P2）；P3 变更须单独重基线 | 见 §2 | — |

### 1.2 非目标

- 不改机制 A 的写盘原子性：取消门之后的"零提交"契约、Ctrl-C 冒烟契约（`windows-ctrl-c-smoke.ps1`）保持逐字不变。
- 不做跨窗口/跨文档的提交流水线（X1.0 冻结的文档级 FIFO 边界不动）。
- 不动解码地板（GPU 工作量）与 mmproj 编码份额（二期 A2d 裁决延续）。
- 不引入 rayon 等新依赖（P1 用 `std::thread` 有界池，窗口深度即上限）。
- 不做 PNG 编码器多线程化（单图 deflate 流串行，不可并行；P4 的快速压缩设置是另一条路）。

## 2. 规则（沿用二期，全阶段有效）

1. 收益判定：<2% 回滚；P1/P2 建议 ≥5%（md-small-20 口径）才合入；P3 属产物集合变更，判据是"消除量 ≥30% 每文档成本 + 评审通过"。
2. 第一档（逐字节）适用 P1/P2：`document.md` + 非计时 `page-*` 与 depth-8 现行冻结参照逐字节一致——**编码并行化/提前化不改变任何字节**（同像素、同编码器、同参数，仅时序变化）。
3. **P3 与 P4 改变产物字节/集合**：`page-*.png` 在逐字节门禁集合内（MAJOR-1 口径）。两者各自需要：全部冻结参照重基线（一次性重跑并归档）+ 行为评审 + `windows-ctrl-c-smoke.ps1`/`real_scan_fault_injection.rs` 断言集核对 + 使用指引更新。P3/P4 与 P1/P2 的门禁互不混写。
4. 门禁次序强制（二期 §2 规则 2 延续）：正确性门禁先行，性能冻结必须采于正确构建。
5. 计时卫生：warm 复测、两遍 <2%、Vulkan 独占重验。
6. 输入钉定：金集 sha256 不变；md fixtures 经 `scripts/build-multidoc-fixtures.py` 重建 + manifest sha256 核对。

## 3. 杠杆总览与排序

| 杠杆 | 内容 | 关键依据 | 预期收益（md-small-20） | 主要风险 | 门禁 |
|---|---|---|---|---|---|
| T1 | step-profile 扩展 commit 段：`render_ms`/`encode_ms`/`write_ms` 逐页计时，`OCRX_STEP_PROFILE` 同通道输出 | §0.2 是推断，先拆分后动手（二期教训：A2a 预判 0.25 µs/step 实测即 no-win） | 决策数据；**P2/P3 目标值据此修订一次** | schema 兼容（沿用 A1 模式） | 数据归档 |
| **P1** | 窗口内多页编码并行（`std::thread` 有界池，上限 = 窗口深度） | §0.2；PNG 单图 deflate 串行但多页天然并行；2 页文档编码墙钟 3.4→1.7 s | ≈−15 s（114→≈99 s） | 核心争用（编码挤占渲染 owner 线程/解码喂数——T1 数据裁决线程数） | 第一档 |
| **P2** | 编码随渲染启动（worker 在每页渲染完成即编码，与同窗解码重叠；取消门后丢弃缓冲，写盘时序不变） | §0.3；编码完躲在 GPU 时间后，commit 剩纯写盘 | P1 之上再 ≈−15~20 s（→≈85 s）；P3 落地后增量有限（编码已消失） | worker panic/中毒路径；内存上界（一窗 × 原始 + 编码缓冲 ≈ 8×(24+4) MB ≈ 224 MB，可接受）；取消语义测试 | 第一档 |
| **P3** | 全页 `page-NNNN.png` 仅 `--keep-pages` 产写；默认路径消除编码+写盘 | §0.2 结构性发现；resume/cleanup 路径均不读它 | **消除**（P1/P2 之后仍 ≈−30 s → ≈55–60 s） | 产物集合变更 → 全部冻结参照重基线 + 外部脚本兼容（有人依赖 page-*.png 存在）；半途失败文档的产物集变化 | 产物重基线评审（独立于第一档） |
| P4 | PNG 编码器快速压缩设置（`CompressionType::Fast`） | 图像页编码 3–10× 提速，文件增大（需实测体积增量） | 与 P1/P2/P3 叠加，图像页为主收益 | 产物字节变更（第二档相似度 + 参照重基线）；`--keep-pages` 产物体积上升 | 第二档 |

**推荐执行序**：`T1 → P1 → P2 → 决策点 {P3, P4}`

- P1 先行：把编码墙钟先砍半，为 P2 的重叠提供更小的隐藏目标；
- P2 在 P1 后实施：worker 池与 P1 的池是同一设施；
- P3 是独立决策点：收益最大但动产物契约，评审材料 = T1 实测 + P1/P2 落点数据；
- P4 仅在 `--keep-pages` 用户反馈体积/速度痛点时启动。

## 4. 阶段计划（TDD）

### T1 提交段插桩（≈0.5 天，`ocrx-runtime`/`ocrx-cli`）

| 项 | 内容 | 产出 |
|---|---|---|
| T1.1 | `StepProfile` 增加 commit 段字段（`render_wait_us`/`encode_us`/`write_us`/`finalize_us`），沿 A1 模式：env-gated、schema 锁测试扩展黄金串、`gpu-resource.json` schema 不变测试回归 | 插桩合入 |
| T1.2 | md-small-20 + 金集各跑一遍汇总，钉死每页 encode/render/write 实测值 | **P2/P3 目标值修订一次**（偏差 >20% 触发条款） |

验收：`docs/test/reports/phase3-t1-<date>-data/` 归档。

### 阶段 P1（≈1 天，`ocrx-output`）

| 项 | 内容（TDD：单测先行） |
|---|---|
| P1.1 | `commit_terminal_pages` 的逐页编码改有界并行：窗口深度即池上限；异常传播语义与现状逐项对齐（任一页编码失败 → 与串行版相同的失败面） |
| P1.2 | 等价性单测：并行版 vs 串行版产物逐字节一致（fake 识别器复用二期测试设施） |
| P1.3 | 门禁：金集两遍逐字节 + md-small-20 两遍计时；核心争用观察（T1 数据对比编码时长是否因渲染线程竞争恶化） |

### 阶段 P2（≈1–2 天，`ocrx-output`/`ocrx-cli`）

| 项 | 内容 |
|---|---|
| P2.1 | 编码 worker：渲染完成即入队编码（队列上界 = 窗口深度）；解码完成后的解析路径只等缓冲、不启动编码 |
| P2.2 | 取消语义测试：取消门触发时在飞编码缓冲全部丢弃、零写盘（机制 A 契约锁定，扩展 Ctrl-C 冒烟断言） |
| P2.3 | worker panic → 与 render 失败同面的页级/窗级失败语义（fail-loud 路径单测） |
| P2.4 | 门禁：金集逐字节两遍 + md-small-20 计时；内存峰值记录（ocrx 进程 working set 口径） |

### 决策点 P3 / P4（各 ≈1 天含重基线，不预设合入）

- **P3**：门控全页 PNG 产写于 `--keep-pages`。评审输入 = T1 消除量实测 + 恢复路径核查（resume/cleanup/审计均不读全页 PNG 的代码级证据）+ 外部消费方排查。通过 → 重基线全部冻结参照 + README/使用指引更新 + 冒烟断言核对。
- **P4**：快速压缩设置数据实测（体积增量/速度比），第二档门禁；仅当 P3 未过且 `--keep-pages` 仍有痛点时启动。

## 6. 风险登记

| 风险 | 缓解 |
|---|---|
| T1 实测推翻 §0.2 推断（编码占比 <30%） | P2/P3 目标值按实修订；<2% 项按规则回滚不硬凑 |
| P1/P2 并行编码挤占渲染 owner 线程或解码喂数 | T1 数据先行；线程池上界 = 窗口深度；两遍计时对比裁决 |
| 取消语义被 P2 破坏（缓冲写盘早于取消门） | P2.2 专项测试 + Ctrl-C 冒烟扩展；写盘代码路径物理不动 |
| P3 破坏外部消费方（脚本/审计依赖 page-*.png） | 评审前仓库内排查 + 使用指引公告；`--keep-pages` 完整保留 |
| 参照重基线引入漂移误判 | 重基线独立提交，重基线前后的非 PNG 产物逐字节比对 |
| worker panic 半途状态 | P2.3 fail-loud 语义测试；checkpoint 恢复路径回归 |
