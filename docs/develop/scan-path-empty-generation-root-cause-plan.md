## 1. 问题陈述（自包含）

**症状**：同一模型文件（sha256 冻结）、同一页图片、同一套参数下：

- **直驱路径**（测试直接调 `LlamaMtmdRuntime::generate_with_progress`）：输出完美。
  例：页 4（300 DPI，2531×3276）→ 3003 字符完整正文，LaTeX 公式/HTML 表格/标题层级全部正确；页 2 → 1391 字符；多次复现。
- **scan 生产路径**（CLI `scan` 全管线）：多页扫描中**约 40–50% 的 OCR 页首尝试输出为空**

## 2. 逻辑核心（定位工作的指导原则）

scan 使用**贪心解码**（temperature=0，逐步 argmax）。贪心解码是确定性的：**输入与解码
状态完全相同 ⇒ 输出逐字节相同**。

实测两条路径对"同页"输出不同 ⇒ **两条路径喂给模型的输入或解码状态必然存在差异**
（或解码本身非确定——见 P4）。因此本立项不需要"猜测原因再验证"，而是**确定性差分**：
把两条路径到达模型边界的全部输入（图片字节、prompt 字节、请求字段、上下文创建参数、
tokenize 输入、线程/采样配置）逐项比对，第一个分歧点即根因所在。

## 3. 已排除假设（均有对照实验，详见接入 spike 记录）

| # | 假设 | 排除实验 | 结论 |
|---|---|---|---|
| H1 | 图像 token 预算不足 | 单页矩阵（scan 页 6：1024→0 字节，2048→2892 字节） | 部分成立，已修（per-model 2048 默认）；修后残余空页 ⇒ 非充分根因 |
| H2 | 窗口批量解码破坏混合 SSM | batch_depth=8 vs 强制串行=1 对照 | 排除（空页集合逐页相同） |
| H3 | 跨页 KV/SSM 状态污染 | 同 runtime 连续生成复用探针 | 排除（直驱复用两页全完整；注意页基准错位，方向性证据） |
| H4 | 模型资产/pin 不兼容 | sha256 冻结校验 + 直驱完美输出 | 排除（模型+pin 本身可用） |
| H5 | 单页 vs 多页的批处理差异 | R2 vs R3 同集合 | 排除（串行化不改变空页） |

## 4. 候选假设（立项待验证，按优先级）

### P1（首要）：渲染交接的图片字节完整性

scan 的页面渲染走**同进程专用 owner 线程 + channel 交接**
（`src/ocrx-scan/src/render/pdfium_owner.rs:1-11`——v1.1 事实校正：非独立进程/IPC），
直驱探针是调用线程内直接渲染。若交接偶发产出不完整/损坏的 RGB 字节（缓冲复用、
stride 错位、channel 传输中的部分写），则：

- 图片字节异常 → 模型首 token 分布异常 → argmax 落在 EOS → 空输出 ✓
- 竞争性/依赖时序的损坏 → **空页集合跨运行非确定** ✓
- 阶梯重试会**重新渲染** → 恢复 ✓（R4 实测 12/12；但见事实校正 2——重试同时更换
  采样链，归因需单变量对照）
- 直驱探针不经 owner 交接 → 从不复现 ✓

### P2（次选）：请求构造/边界转换的隐性差异

scan 路径经 `adapter.encode → encoded_to_worker_task → WorkerTask`，直驱路径直接构造
`InferenceRequest`。两者字段映射若有细微差异（图片字节切片、prompt、参数缺省值），
在贪心确定性下即产出不同输出。注意 v1.0 的"同页"结论受页基准错位影响，P2 的验证
必须以 v1.1 的对拍协议重做。

### P3（再次）：actor 上下文/解码循环的路径差异

actor 的 `Generate` 处理与直驱 `generate_with_progress` 在上下文创建参数（n_ctx、
线程数、batch 参数）、tokenize 参数、解码循环实现上的细节差异。

### P4（兜底候选）：解码本身的多线程非确定性

若差分证明字节、请求字段、上下文参数、解码路径**全部相同**而输出仍跨运行不同，
则确定性假设被打破——指向 llama.cpp 多线程解码的归约顺序非确定性（运行间 logits
微差 + 模型近平局首 token 分布 → EOS 间歇胜出）。该分支的修复方向为解码确定性
配置（如 ovisocr3 串行页的单线程解码），且**必须先完成同输入字节下仅切换线程配置
的对照实验**再定性。

### 判定规则（v1.1 BLOCK-2 修复：分支化闭环）

- E1 **发现字节/字段差异** → 分歧层 ∈ {P1, P2}：Phase B1 修复 + 字节一致性回归
  （先红后绿）；SP-T04 三连扫 + "已修复"闭环。
- E1 字节相同 → E3 状态/参数差分；**发现参数/状态差异** → 分歧层 ∈ {P3}：Phase B2
  修复 + 归档请求重放回归（含分层实际值断言）；SP-T04 三连扫 + "已修复"闭环。
- E3 亦无差异（字节/参数/状态/解码路径全同而输出跨运行不同）→ **P4 定性实验**
  （同输入仅切线程配置）；确认后 Phase B2' 修复（确定性解码配置）+ 运行间稳定性
  统计回归；SP-T04 三连扫 + "已修复"闭环。
- 若重放判别在归档请求上无法复现空输出（重放空率为 0）→ 复现依赖归档外状态，
  登记该线索（指向 P1 方向的时序依赖），**回到 Phase A 补充取证**；此为循环出口，
  每轮必须带来新证据，两轮无进展则按"证据链推进"诚实收口并由后续计划接手。

## 5. 分阶段任务

### Phase A：取证工具化与判别实验（SP-T01/T02）

- **SP-T01 边界仪器化**（env 门控，不动生产行为）：
  - **页身份约定（冻结）**：对外记录一律 1 基 `page_number`；渲染调用显式计算
    `page_index = page_number - 1`；每条记录**同时写两个字段**。
  - **`BoundarySample` JSONL 记录键（双侧同 schema）**：
    `input_sha256`、`run_id`、`source`（scan|direct）、`page_number`、`page_index`、
    `attempt`、`window_id`、`slot`、`rgb8_len`、`rgb8_sha256`、`prompt_sha256`、
    `width`、`height`、`max_output_tokens`、`image_tokens_override`、`retry_sampling`、
    `outcome`（empty|nonempty）、时间戳。
  - **采集点**：
    - scan 侧：**encode 边界**（`EncodedTask` 仍携带 `ImageInput.id`，可从 id 解出
      `page-N[-band-M]` 页身份）+ 串行/窗口调用点（`page`/`attempt`/`window_id` 在
      调用方作用域内）——`WorkerTask` 无页码/attempt/run 字段，**不作为采集点**
      （`backend.rs:75-90` 转换丢弃 `ImageInput.id`，v1.0 设计在此失效）；
    - direct 侧：探针内，渲染前显式换算 `page_index`，记录双字段。
  - **attempt 语义（v1.2 收窄）**：仅 scan **attempt-1** 与直驱对拍（直驱恒
    attempt=1）；attempt≥2 的重试记录不参与双路径对拍（direct harness 若需重放
    attempt≥2 的 grid/sampling/上下文状态，属归档重放数据集的扩展，不改变本硬门）。
- **SP-T02 判别实验 E1/E2/E3**：
  - **对拍前置校验（硬性，作用域 = E1 的 attempt-1 数据集，v1.2 修订）**：每条
    **纳入 E1 的 scan attempt-1 记录**必须恰好匹配一条**同 `page_number`、同参数、
    direct attempt=1** 的记录；该数据集内缺失或重复匹配 ⇒ 实验无效，禁止输出任何
    根因结论。**attempt≥2 的阶梯重试记录不进入该对拍、也不触发无效判定**——它们是
    目标故障的组成部分（首尝试空页触发恢复），转入归档请求重放（B2）与单变量对照
    （E 阶段）数据集。
  - E1：匹配对上比对 `rgb8_sha256`/`prompt_sha256`/全部请求字段；差异 ⇒ 导出两侧
    缓冲落盘做模式 diff（全零区/行错位/尾部垃圾各指向不同损坏类）。
  - E2（E1 字节相同）：WorkerTask 字段与 actor 上下文创建参数逐项比对（n_ctx、线程
    数、batch 参数、tokenize 输入全文）。
  - E3（E2 亦相同）：解码非确定性检查——同路径同输入重复 N 次生成，统计输出是否
    跨运行一致（P4 定性）。
  - **单变量对照实验（v1.1 事实校正 2）**：归档一份空页输入字节后，分别仅切换采样
    链、仅重新渲染，归因 R4 的恢复变量。
  - 完成判定：对拍前置校验通过 + 以确定判据回答"输入字节是否差异"，并给出第一个
    分歧层。

### Phase B：修复（SP-T03，按 §4 判定规则分支）

- **B1（分歧层 = P1/P2，输入字节/字段差异）**：
  - 修复字节/字段完整性（交接同步或校验、渲染或传输修正、构造对齐）；
  - 回归：**双路径同页同参字节一致性测试**——修复前必红（E1 已证差异），修复后必绿。
- **B2（分歧层 = P3，上下文/tokenize/采样/线程参数差异）**：
  - 修复参数/状态差异；
  - 回归：**归档失败请求原样重放**判别测试——修复前以归档记录的空率复现立即 EOS
    （N≥20 重放统计），修复后在**相同输入、相同上下文参数、相同解码路径**下恢复
    非空；并按分歧层分别断言实际值（tokenize/chunk 序列、上下文参数、采样状态）；
  - 重放空率为 0 的子分支 → 按 §4 循环出口回到 Phase A。
- **B2'（分歧层 = P4，解码非确定性）**：
  - 修复解码确定性配置（如 ovisocr3 串行页单线程解码）；
  - 回归：同输入重复 N 次生成的运行间一致性统计测试——修复前存在输出不一致（或空
    输出间歇），修复后 N 次全部一致且非空。
- 通用完成判定：分歧点消除，该层判别测试钉死；**禁止以未红的测试宣称修复**。

### Phase C：验收（SP-T04，仅 B1/B2/B2' 实际完成修复的分支适用）

- 30 页复合扫描（默认参数，ovisocr3 quality）**连续 3 次**：
  **0 个首尝试空页、0 次阶梯重试**、30/30 完成、退出码 0；
- 墙钟回落到无重试量级（参考 ovisocr2 同页 528s；串行 + 2048 网格固有成本存在，
  以"0 重试"为准绳，不硬定秒数）；
- ovisocr2 全门禁 + 字节不变集 golden 全绿（修复只在共享路径的完整性/确定性语义上）；
- 检空安全网**保留不删**（兜底语义），其判别测试继续通过；
- 全部门禁：fmt/clippy/test/architecture/release-scripts。

### Phase D：收口（SP-T05，按分支）

- **B1/B2/B2' 修复分支**：本计划结论回写接入验收报告 §质量差距（根因 + 修复 + 复验
  数据），登记"已定位/已修复"。
- **证据链出口（§4 循环出口两轮无进展）**：以"根因未定位、证据链推进"收口并重立项；
  **本分支下 §8 第 3 条（三连扫与修复验收）不适用，且不得登记根因已定位或问题已
  修复**——验收报告 §质量差距相应更新为证据链现状。

## 6. 边界与非目标

- 不动模型资产（sha256/pin 冻结）；不动 `DECODE_GENERATION=3`；
- 不动检空安全网与退化阶梯语义（保留为兜底）；
- 不做 OvisOCR3 能力扩展（结构化/KIE/双图仍为非目标）；
- 不改默认模型（D-GATE 独立决策）；
- GPU 环境的复现性验证不在本立项范围（本机 CPU-only）；
- 不触碰推理平台冻结契约（`TaskRequest`/`TaskResponse`/`EncodedTask` 公共形态——
  页身份经 `ImageInput.id` 与带外 JSONL 携带，不加协议字段）。
