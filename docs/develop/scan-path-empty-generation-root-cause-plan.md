**状态：** 已立项，待实施（2026-11-15）
**来源：** OvisOCR3 接入验收报告（`ovisocr3-integration-acceptance-report.md` §质量差距）最高优先遗留；代码评审 PASS 留言同向。
**前置：** OvisOCR3 接入已合并（PR #13，merge `b198d6b`）；检空安全网已落地（空输出进阶梯、耗尽显式退化、续扫不复用）。

## 1. 问题陈述（自包含）

**症状**：同一模型文件（sha256 冻结）、同一页图片、同一套参数下：

- **直驱路径**（测试直接调 `LlamaMtmdRuntime::generate_with_progress`）：输出完美。
  例：页 4（300 DPI，2531×3276）→ 3003 字符完整正文，LaTeX 公式/HTML 表格/标题层级全部正确；页 2 → 1391 字符；多次复现。
- **scan 生产路径**（CLI `scan` 全管线）：多页扫描中**约 40–50% 的 OCR 页首尝试输出为空**
  ——模型立即产生 EOS，页面 0 字节。空页集合**跨运行非确定**（同一命令两遍，空页集合不同）。

**关键运行数据**（全部为 30 页复合 `ovisocr2-draft-v1/inputs/source.pdf`，input_sha256
`ab323551…`，CPU，ovisocr3 quality/Q8_0 @ michalland `7be644a3…`，pin 0.1.161/`d8123504…`）：

| 运行 | 配置 | 首尝试空页 | 备注 |
|---|---|---|---|
| R1 | 1024 网格，窗口批量 | 14/27 | 页 6 空 |
| R2 | 2048 网格（per-model 默认），窗口批量 | 14/27 | 页 6 恢复、页 4 变空——集合与 R1 不同 |
| R3 | 2048 + 串行地板（batch_depth=1） | 14/27 | **集合与 R2 逐页相同** |
| R4（评审复跑） | 2048 + 串行 + 检空安全网 | 12/27 首尝试空 | **全部在第 3 次尝试（重试采样链）恢复非空**；18/29 为空白路由页；30/30 完成，退出码 0，墙钟 ≈1535s |
| 对照：ovisocr2 同页同参 | 1024 网格，窗口批量 | **0** | 30 页全完整（~47K 字符），528s |
| 直驱探针 ×N | 同页同参 | **0**（从未复现） | 含跨页上下文复用探针（页 2→页 4 同 runtime 连续生成，均完整） |
| CLI 单页扫描 ×N | 同页同参 | **0**（从未复现） | |

## 2. 逻辑核心（定位工作的指导原则）

scan 使用**贪心解码**（temperature=0，逐步 argmax）。贪心解码是确定性的：**输入与解码
状态完全相同 ⇒ 输出逐字节相同**。

实测两条路径对同一页输出不同 ⇒ **两条路径喂给模型的输入或解码状态必然存在差异**。
因此本立项不需要"猜测原因再验证"，而是**确定性差分**：把两条路径到达模型边界的
全部输入（图片字节、prompt 字节、请求字段、上下文创建参数、tokenize 输入）逐项
比对，第一个分歧点即根因所在。

附带线索：救回空页的 rung 2 仅更换采样链（repeat_penalty 1200 milli）——EOS 以微弱
优势赢下 argmax、加惩罚即被绕开 ⇒ 空页时模型的首 token 分布处于接近平局的边缘 ⇒
与"输入字节处于轻微异常状态"高度相容。

## 3. 已排除假设（均有对照实验，详见接入 spike 记录）

| # | 假设 | 排除实验 | 结论 |
|---|---|---|---|
| H1 | 图像 token 预算不足 | 单页矩阵（页 6：1024→0 字节，2048→2892 字节） | 部分成立，已修（per-model 2048 默认）；修后残余空页 ⇒ 非充分根因 |
| H2 | 窗口批量解码破坏混合 SSM | batch_depth=8 vs 强制串行=1 对照 | 排除（空页集合逐页相同） |
| H3 | 跨页 KV/SSM 状态污染 | 同 runtime 连续生成页 2→页 4 复用探针 | 排除（直驱复用两页全完整） |
| H4 | 模型资产/pin 不兼容 | sha256 冻结校验 + 直驱完美输出 | 排除（模型+pin 本身可用） |
| H5 | 单页 vs 多页的批处理差异 | R2 vs R3 同集合 | 排除（串行化不改变空页） |

## 4. 候选假设（立项待验证，按优先级）

### P1（首要）：异步渲染交接的图片字节完整性

scan 的页面渲染走**独立 pdfium owner 进程**（渲染完经 IPC 传回主进程），直驱探针是
**同进程同步渲染**。若 owner 交接偶发产出不完整/损坏的 RGB 字节（缓冲竞争、未初始化
读、stride 错位），则：

- 图片字节异常 → 模型首 token 分布异常 → argmax 落在 EOS → 空输出 ✓
- 竞争性损坏 → **空页集合跨运行非确定** ✓
- 阶梯重试会**重新渲染** → 第二次拿到完好字节 → 恢复 ✓（R4 实测 12/12）
- 直驱探针不经 owner → 从不复现 ✓
- 单页扫描渲染次数少 → 触发概率低 ✓（从未观测 ≠ 不可能）

证据链四条现象全部自洽，故列为首要假设。

### P2（次选）：请求构造/actor 路径的隐性差异

scan 路径经 `adapter.encode → encoded_to_worker_task → WorkerTask`，直驱路径直接构造
`InferenceRequest`。两者字段映射若有细微差异（如图片字节切片、prompt 拼接、参数缺省
值），在贪心确定性下即产出不同输出。

### P3（再次）：actor 上下文/解码循环的路径差异

actor 的 `Generate` 处理与直驱 `generate_with_progress` 在上下文创建参数、tokenize
参数、解码循环实现上的细节差异。

### 判定规则

E1 字节比对（见 §5）若**发现差异** → P1/P2 走向，按差异模式继续二分；
若**字节完全相同** → P1/P2 证伪，转向 P3 及解码状态差分（ honest 登记：届时根因在
更深处，按新证据重新立项）。

## 5. 分阶段任务

### Phase A：取证工具化与判别实验（SP-T01/T02）

- **SP-T01 边界仪器化**（env 门控，不动生产行为）：
  - scan 路径：在 `WorkerTask` 构造完成处记录 `sha256(rgb8)` + `sha256(prompt)` +
    全字段（width/height/max_tokens/override/sampling）；
  - 直驱对照 harness：现有 `src/ocrx-runtime/tests/ovisocr3_raw_probe.rs` 扩展同名
    记录；
  - 两侧记录写入可比对的 JSONL。
- **SP-T02 判别实验 E1/E2**：
  - E1：同页同参双路径运行（多页 + 多次迭代），逐 attempt 比对字节校验和；
  - E2：差异模式分析——若不同，导出两侧缓冲落盘 diff（全零区/行错位/尾部垃圾各自
    指向不同损坏类）；若相同，进入 E3（WorkerTask 字段与 actor 参数逐项比对）。
  - 完成判定：以确定判据回答"输入字节是否差异"，并给出第一个分歧点。

### Phase B：修复（SP-T03）

- 按 E 阶段判定的分歧点修复（竞争→同步/校验；字节差→渲染或传输修正；字段差→构造
  对齐）；
- **回归测试先行**：同页双路径字节一致性测试（多迭代），修复前必红、修复后必绿；
- 完成判定：分歧点消除，测试钉死。

### Phase C：验收（SP-T04）

- 30 页复合扫描（默认参数，ovisocr3 quality）**连续 3 次**：
  **0 个首尝试空页、0 次阶梯重试**、30/30 完成、退出码 0；
- 墙钟回落到无重试量级（参考 ovisocr2 同页 528s；串行 + 2048 网格本身有固有成本，
  以"0 重试"为准绳，不硬定秒数）；
- ovisocr2 全门禁 + 字节不变集 golden 全绿（修复只在共享路径的完整性语义上，不改变
  ovisocr2 既有输出字节）；
- 检空安全网**保留不删**（兜底语义），其判别测试继续通过；
- 全部门禁：fmt/clippy/test/architecture/release-scripts。

### Phase D：收口（SP-T05）

- 本计划结论回写接入验收报告 §质量差距（根因 + 修复 + 复验数据）；
- 若 E1 证伪 P1/P2：诚实登记新证据链与下一步计划，本计划以"根因未定位、证据链推进"
  形态收口，不虚报。

## 6. 边界与非目标

- 不动模型资产（sha256/pin 冻结）；不动 `DECODE_GENERATION=3`；
- 不动检空安全网与退化阶梯语义（保留为兜底）；
- 不做 OvisOCR3 能力扩展（结构化/KIE/双图仍为非目标）；
- 不改默认模型（D-GATE 独立决策）；
- GPU 环境的复现性验证不在本立项范围（本机 CPU-only）。

## 7. 风险

| # | 风险 | 处理 |
|---|---|---|
| R1 | 非确定性导致复现不稳定 | E1 用多迭代校验和 + 落盘 diff 取证；每次运行全程记录 |
| R2 | 根因在 E1 证伪 P1/P2 后仍未定位 | §5 判定规则已内置诚实出口：交付证据链 + 重立项，不虚报 |
| R3 | 修复触及 owner 进程协议（IPC） | owner 协议在本仓代码内，可改；改协议需同步更新其测试 |
| R4 | 修复影响 ovisocr2 | 全部 golden + 门禁守卫；修复语义为"完整性"而非行为变更 |

## 8. 验收标准（汇总）

1. SP-T02 产出确定判据：**"scan 与直驱到达模型边界的输入是否存在差异"有可复现的
   实验答案**（差异或无差异，均有证据文件）；
2. 若有差异：分歧点修复 + 双路径字节一致性回归测试（先红后绿）；
3. SP-T04 三连扫验收通过（0 空页/0 重试/门禁全绿/ovisocr2 不变集不动）；
4. 全程证据（校验和记录、diff、运行日志）归档 `docs/develop/spike-assets/` 或
   `docs/test/reports/`；
5. 文档闭环：验收报告 §质量差距更新为已定位/已修复（或证据链推进的诚实登记）。
