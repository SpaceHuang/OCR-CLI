# Phase-3 fallback 裁决：P1/P2/P3 全部 no-go（T1 数据裁决）

**日期**：2026-11-05
**计划依据**：v2.1 §3.4 执行序——"每项独立过线才实施，**未过线即关闭并归档，不硬凑**"；§4 Fallback 节。
**数据依据**：`docs/develop/phase3-t1-2026-11-05.md`（T1.4 实测）+ `docs/test/reports/phase3-t1-2026-11-05-data/`；模型 = 附录 A 修正收益模型（v2.1 BLK-5 修正版，单页/两页/退化重试三场景手算核验见 §4）。

## 裁决

| 杠杆 | 采纳线 | T1.4 实测代入 | 判定 |
|---|---|---|---|
| P1（EncodePipeline，编码与同窗解码重叠） | md-small-20 ≥5% | E=0.018 s/文档（18 ms，两页合计）≪ D=0.67 s → 编码全额隐藏，收益=E=0.36 s → 18.5→18.14 s ≈ **−1.9%**；金集 −1.4%（<2% 回滚线） | **NO-GO** |
| P2（触发前移至渲染完成） | 同上 | P1 后 E 已全额隐藏（max(0, E−D−R)=0），增量=0 | **NO-GO**（增量不存在） |
| P3（全页 PNG 仅 `--keep-pages`） | 消除量 ≥30% 每文档成本 | 消除 encode+write+finalize ≈0.030 s/文档 → 编排墙钟 −3.2%；占比 0.030/0.93=3.2%（文档口径）或 0.030/0.185=16%（提交段口径），**均 <30%** | **NO-GO** |

## 关键事实链

1. **render_wait（0.155 s/文档）不是 P1 可隐藏对象**：其主导成分是页 1 demand 渲染的调用者等待（行级：页 1 owner≈65 ms demand、页 2 owner≈20 ms 预取命中）——渲染在识别入口**之前**完成，编码流水线与它无重叠关系；能重叠的只有 encode 本身（18 ms）。K=2 预取已把渲染段压到 T1.4 所示水平（一期 P3 交付继续有效）。
2. **encode 已被二期整改压到 18 ms/文档**（v1.0 估计 1.5–2 s/页 → 校准 0.05–0.15 s/页 → 实测 ≈9 ms/页）：P 杠杆的假想对象在实测中不复存在。
3. 提交段三段合计 0.185 s/文档（19.9% 份额），其中 render_wait 0.155 s 属渲染供给问题（更深预取属独立提案，本计划非目标），encode+write+finalize 0.030 s 为 P 杠杆全部可达对象——**上界 −3.2%**。
4. 金集口径：提交段 2.07 s / 28.56 s = 7.2%，可隐藏（编码重叠）份额 0.40 s → −1.4%，同样不构成杠杆。

## 附录 A 模型核验（手算，公式未入产品故无 rust 单测）

- 单页/depth-1 尾窗：Δ_overlap=0，P2 不减 R——与 v2.0 评审 BLK-4 反例（R=2、D=1、E=2 → 4 s+W）一致；
- 两页窗口（md20 形态）：页 1 编码可与页 2 渲染重叠（Δ ≤ 页 2 渲染时长），两页编码与 D=0.67 s 重叠——E 全额隐藏，无暴露尾差；
- 退化重试：attempt-1 编码缓冲失效不计入（终态 totals 口径已由 T1 recorder 锁定）。

## 处置

- **不实施** P1/P2/P3；EncodePipeline/数据拆分/`--keep-pages` 门控全部不进代码——以 T1 数据归档为关闭证据。
- **保留资产**：T1 commit-profile 通道（`8fbe735`）为两主线通用诊断设施，随分支保留；后续任何提交路径优化提案以 `commit-profile.json` 为第一测量工具。
