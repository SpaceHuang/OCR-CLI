### 每步/每 token 归因（30.43 s 拆到 100%）

| 分段 | 占窗口 | 每 token | 定性 |
|---|---:|---:|---|
| decode_wait（`context.decode` 阻塞） | 43.9% | 1.04 ms | GPU 图执行 + 全量 logits DtoH（`needs_raw_logits` 路径）；与 batched-bench 下界（12 812 ÷ 1030 ≈ 12.4 s）差 ≈0.9 s（尾窗低占用） |
| **logits_ffi（逐槽 `get_logits_ith`）** | **34.6%** | **0.82 ms** | 每次调用内部 `ctx->synchronize()`（`llama-context.cpp:3574`，钉定 sys 0.1.153 实读）；首调用吸收异步 DtoH 完成等待 + Vulkan 同步开销 |
| argmax（Rust 侧贪心扫描） | 11.3% | 0.27 ms | `max_by(total_cmp)` 闭包形态不可向量化，151 936 f32/行 |
| encode（mmproj `eval_chunks`） | 5.9% | 0.14 ms | GPU 工作量，host 优化不可消除（方案 §0.3④） |
| slot_setup（bitmap+tokenize） | 2.5% | 0.06 ms | host，每窗每槽一次（非每步） |
| residual（进度消息/分配/拆除） | 1.7% | — | — |
| batch_build | **0.004%** | 0.25 µs | `LlamaBatch::new` 每步 4-token 小分配，实测可忽略 |
| detokenize | 0.04% | — | 64 字节 CString FFI，可忽略 |
| ring（环检测） | 0.0003% | — | 256-token 环扫描，可忽略 |

### 结论：A 阶段目标值修订（方案 §4 阶段 A 预案修订）

1. **A2a（batch 复用/降分配）**：实测 0.25 µs/step、1.3–1.5 ms/scan —— **<2% 规则判定不实施**（数据记录在案，无需实现后回滚）。
2. **A2c（环检测降频）**：0.1 ms/scan —— **不实施**（环检测触发点位移会破坏第一档语义，而其成本本身可忽略）。
3. **A2b（逐槽 FFI 合并）拆两半**：
   - **FFI 调用数合并：钉定绑定下不可实现**。`llama-cpp-2 0.1.152` 未暴露 `llama_set_sampler` / `llama_get_sampled_tokens` 等 backend-sampler 批量接口（sys 0.1.153 C API 已有，wrapper 未跟进；workspace `unsafe_code = "forbid"` 排除直连 sys）。每步 N 次 `synchronize` 为绑定固有成本。解除路径：升级 wrapper（违反 WP.2 冻结，另行提案）或解禁 unsafe（独立提案）。
   - **argmax 循环外提（A2b-argmax）**：`max_by` 闭包 → total-order i32 key 循环（LLVM 可向量化，`f32::total_cmp` 语义 + last-max 平局逐位等价，属性测试锁定）——**已实施**，见阶段 A 报告。
4. **A2d（编码/解码重叠）**：encode+slot_setup 合计 2.56 s（8.4% 窗口 / 6.4% 墙钟上界）为理论隐藏上界；涉及 actor 协议扩展（eval_chunks 交错），维持"仅评估不承诺"裁决 → **不做**（收益上界 2.5 s < C 阶段单项收益，且协议复杂度高）。
5. **修订后的 A 目标**：可兑现份额 = argmax ≈1.7 s（墙钟 ≈4.3%）；解码段 30.4 → ≈28.7 s，墙钟 40.2 → ≈38.3 s。方案 v1.2 的"解码 ≤22 s"预案**不可兑现**（缺口的 34.6% 是绑定固有同步 + 43.9% 是 GPU 地板），M1 上界 23–26 s 撤回，按 §5 规则以 T0.1 实测修订。
