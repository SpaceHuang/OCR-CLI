## 2. 三项归因（commit-profile / step-profile 实测）

1. **depth-16（−5.9% 单项）**：窗口 4→2，陪跑步数 3,543→2,031，平均活跃槽 3.6→6.3；logits_ffi 8.03→5.01 s（步数减少）。
2. **整窗预取（W2）**：render_wait 1.50→1.73 s——**修正 W2 的一个错误预期**：单窗前瞻（K=窗深）在解码期间无人发请求而停摆，K=2×窗深（当前+下一窗）实测也仅回收 ≈0.1 s——余量 1.7 s 的主体是**首窗渲染（16 页 ≈0.96 s），其之前没有任何解码可藏**，结构性不可消；K=32 的边际收益仅 0.6%。
3. **编码流水线（W3）**：png_encode 0.45 s + commit_write 0.20 s 移出临界路径（与解码并行），墙钟收益 ≈0.5-0.7 s；TDD 矩阵 4 项全过（终态代次 [2]≠[1]、编码错误→页级 recognize 诊断、panic fail-loud、流水线/fallback 字节等价）。

剩余构成（30.7 s）：解码 GPU 段 ≈12.5 s + logits_ffi ≈5 s（wrapper 提案）+ mmproj encode 1.75 s + 首窗渲染 0.96 s + 校验加载 5.3 s + argmax/杂项 ≈4 s。

## 4. 边界与移交

- md-small-20（2 页文档×20）：27.6 s ≈ 基线 26.2 s（日漂移带内）——2 页文档窗口永远欠填充，**批深/预取/编码三项均无收益**，与方案预期一致；
- depth 12（kernel 量化坑 −11%）永久跳过；depth >16 需先解除 logits_ffi（wrapper 提案），否则 host 路径随槽位增长的论断已被本轮数据修正（logits_ffi 随总 token 数而非槽位数），但 16 的 kernel 天花板（B=16 ≈ B=14 持平）决定无更深空间；
- 低显存卡（<12 GiB）维持 depth 8——6 GB 冻结规则保护不变。
